# KiCad AI Assistant · 使用说明

> 版本 0.1.0 · 服务器部署目录 `/opt/Ki-Agent` · 代码仓库 https://gitee.com/wjc1238765/kicard-ai

---

## 1. 这是什么

一个 **自研的 KiCad 智能助手 Agent**（LangGraph + Deep Agents），通过网页多用户使用：

```
浏览器 (React)  ──►  我们的 Agent 服务 (FastAPI + LangGraph/Deep Agents)   ← 单个进程 / 单个容器
                          │
                          ├─ 内置工具（53 个，无需安装 KiCad）：读板 / 移动对齐 / DRC / 网表 / 快照 …
                          │
                          └─ 开源插件 KiCad-AI-Assistant（PyPI 包 `kcaa`）—— 作为库装在同一进程内，
                             其 116 个工具函数被直接包装为 Agent 工具调用，**不经过 MCP**
                             （符号/封装库检索、层次图纸、布线、铜皮区域、分组、IPC …）
```

- **我们的 Agent** 负责：多用户登录、每个用户独立的工程工作区与对话、系统提示（KiCad 坐标系与硬性规则）、
  任务规划、子代理、人工确认、自动快照、长期记忆、流式 UI。
- **开源插件 (kcaa) 的调用方式**：插件里的每个工具本质上都是普通 Python 函数（`kcaa/tools/*.py`），MCP 只是它对外的
  一层传输协议。我们在 `backend/app/agent/tools/kcaa_direct.py` 中导入 `kcaa`，收集这些函数及其参数 schema，
  用一个极简的上下文对象替代 FastMCP 的 `Context`（只提供日志、进度、缓存），直接在进程内调用——没有 MCP 服务器、
  没有第二个容器、没有网络开销。同名工具优先用我们的内置实现（它们感知用户工作区），其余 81 个自动并入「可用工具」。
- 集成方式可在后台「系统设置」切换：`direct`（默认，进程内直连）/ `mcp`（连接外部 MCP 服务器，需另装适配器）/ `off`（仅内置工具）。

## 2. 快速上手（使用者视角）

### 2.1 首页 / 登录 / 注册

打开 **http://139.224.189.163:8080** 进入产品首页（功能介绍、工作流程、技术架构）。右上角「登录」或「免费注册」进入账号页；登录后进入工作台 `/app`。
首次使用点「注册」（密码 ≥ 6 位）。**第一个注册的账号自动成为管理员**（当前服务器数据库为空，你注册的第一个账号即管理员）。

| 路径 | 说明 |
| --- | --- |
| `/` | 产品首页（未登录可见） |
| `/login` | 登录 / 注册（管理员关闭注册后只显示登录） |
| `/app` | 对话工作台 |
| `/admin` | 后台管理（仅管理员；工作台左下角「后台管理」入口） |

> 端口说明：服务器安全组只放行了 80/443/8080/3000/8093/8443，8000 不通，因此应用映射在 **8080**。

### 2.2 选择或导入工程

右侧「当前工程」→「切换工程」：

| 方式 | 说明 |
| --- | --- |
| 加载示例：power_module | 一块 AMS1117 LDO 电源小板，去耦电容故意放得离芯片很远，适合体验「优化布局 + DRC」 |
| 导入 ZIP 工程 | 把整个 KiCad 工程目录打包成 zip 上传（含 `.kicad_pro/.kicad_sch/.kicad_pcb`） |
| 上传单个文件 | 直接上传 `.kicad_pcb` / `.kicad_sch` / `.kicad_pro` |

每个用户的文件保存在自己的私有工作区，Agent（包括 kcaa 工具）**只能访问自己的工作区**，越界路径会被拒绝。

### 2.3 对话

在输入框描述任务，`Enter` 发送、`Shift+Enter` 换行。示例：

- 「帮我优化一下电源模块的布局，电容尽量靠近芯片的电源引脚，并检查是否有 DRC 问题。」
- 「读取当前 PCB 的板级信息，列出所有元件的位置。」
- 「运行 DRC 检查并解释每一条违规。」
- 「检查原理图有没有未连接的引脚或参考号冲突。」
- 「把 J1、J2 对齐到同一 Y 坐标，然后把 C1、C2 等距分布。」
- 「搜索一个 0603 的 LED 封装并把 D1 的封装改成它。」（需要 kcaa 工具）

界面元素：

| 元素 | 含义 |
| --- | --- |
| 工具调用卡片 | Agent 正在/已经调用的工具；点击展开参数与结果；`执行中…` / ✅ / ❌ |
| DRC 卡片 | `run_drc_check` 的结果：通过（绿）/ 警告（黄）/ 错误（红），可展开每条违规与坐标 |
| 任务清单 | 复杂任务时 Agent 的分步计划与完成状态 |
| 可视框选 | 右侧预览点「框选对象」，可单击或拖框选择 PCB 封装/原理图符号，再引用到对话中的“这些对象” |
| 项目设计约束 | 右侧当前工程点「设计约束」，保存栅格、线宽、间距、过孔、板边和器件高度要求 |
| 整批修改确认 | Agent 先展示所有拟执行动作、具体参数和验证步骤；点「批准并执行」后由系统按顺序自动执行（每步先快照，计划卡片实时显示每项进度与差异），助手只负责复查与汇报；也可整批拒绝 |
| 后台运行 | 任务在服务端后台执行：刷新页面、切换对话或网络抖动都不会中断，回来后自动接上实时输出；侧栏运行中的对话有蓝色标记；只有点「停止」才会取消 |
| 设计质量审查 | 右侧点「设计审查」，统一查看 ERC、DRC、布局四项分数和问题清单；可生成整批自动修复计划 |
| ECO 一致性 | 右侧点「ECO」，比较原理图与 PCB 的器件、值、封装、网络差异；缺失封装/值/网络可整批同步，多余封装与封装型号差异保留人工判断 |
| 预览放大 | 点击右侧预览图或放大按钮，站内大图可缩放、切换 PCB/原理图，并可在新窗口打开 |
| BOM/DFM | 右侧点「BOM/DFM」，按值+封装归并物料，检查缺失封装/值、重复位号、封装是否在库、超小封装、双面贴装；可导出 CSV |
| 电路向导 | 右侧点「电路向导」，选择 LDO 电源、LED 指示、分压采样、去耦电容组、USB-C 取电、RS-485 模板；参数实时计算（E24 选值），符号/封装对照服务器 KiCad 库校验，放置前需整批批准 |
| 布局预览 | 右侧实时渲染 PCB/原理图；Agent 修改文件后自动刷新并标注「已更新」 |
| 在 KiCad 中打开 | 下载完整工程 ZIP；解压后双击 `.kicad_pro` 打开 |

### 2.4 快照与回滚

Agent **每次修改文件前都会自动保存快照**。顶部「会话快照」可以查看、手动创建、一键恢复到任意快照（恢复前会再自动备份一次当前版本）。

### 2.5 技能 (Skills)

顶部「技能 (Skill)」查看内置工作流：`pcb-power-layout`（电源布局）、`drc-fix`（DRC 修复）、`schematic-review`（原理图审查）。
Agent 会在任务匹配时自动读取；也可以点「在对话中使用」显式要求。
新增技能：在 `backend/app/agent/skills/<名称>/SKILL.md` 添加带 `name/description` 头部的 Markdown 后重启服务。

### 2.6 长期记忆

「设置」→「长期记忆」是 Deep Agents 自带的 `AGENTS.md` 记忆文件（**每个用户独立**）。
当你说「记住我习惯用 0.05 mm 栅格」这类偏好时，Agent 会自动写入；也可以直接在这里编辑。它会在每次对话开始时注入系统提示。

### 2.7 多用户

- 右侧「在线用户」实时显示当前在线的人；黄点表示对方的 Agent 正在处理任务。
- 每个对话同一时刻只处理一条消息；对话、工程、记忆、快照全部按用户隔离。

工作台左下角「后台管理」或直接访问 `/admin`：

| 页面 | 功能 |
| --- | --- |
| 总览 | 注册/在线/对话/工程等统计，Agent 当前模型、工具数、MCP 连接状态、kicad-cli、运行时长、Token 累计、最近注册用户，最近一次重建错误提示 |
| 模型配置 | 一键预设（2026-09 现行型号：OpenAI GPT-5.6 / Claude Opus 5 · Sonnet 5 / DeepSeek V4 / 通义千问 Qwen3.8-Max · 3.7-Plus / Kimi K3 / GLM-5.3 / Ollama / 离线演示），提供方、模型名、API Key（加密存储、掩码显示、留空保留）、Base URL、温度、上下文窗口、max_tokens；**「测试连接」**发送一句 ping 校验；**「保存并热重载」**立即重建 Agent，不需要重启容器 |

| 系统设置 | **品牌**：上传 Logo（PNG/SVG/JPG/WebP ≤ 2 MB，所有页面即时生效，可恢复默认）、站点名称、副标题；开放注册开关、子代理开关、Agent 最大步数、开源插件集成方式（direct / mcp / off）与工具集（full / plugin） |

后台保存的配置写入数据库 `app_settings` 表，**优先级高于 `.env`**，容器重启后仍然生效；要回到 `.env` 的值，删除对应记录即可：

```bash
docker compose exec app python -c "import sqlite3;c=sqlite3.connect('/data/app.db');c.execute('delete from app_settings');c.commit()"
docker compose restart app
```

## 3. 服务器部署与运维（Docker）

### 3.1 目录结构

```
/opt/Ki-Agent/
├── .env                      # 运行配置（LLM 密钥等，不进 git；后台保存的配置优先于它）
├── docker-compose.yml        # 单个 app 服务（内含开源插件 kcaa 库），SQLite 持久化
├── docker-compose.postgres.yml  # 可选：叠加 PostgreSQL
├── Dockerfile
├── backend/  frontend/  docs/
```

数据（数据库、用户工作区、快照、Logo）在 Docker 卷 `ki-agent_appdata`，容器内路径 `/data`。

### 3.2 常用命令

```bash
cd /opt/Ki-Agent
docker compose ps                       # 状态
docker compose logs -f app              # 应用日志（含 Agent 启动、工具数量、开源插件加载）
docker compose restart app              # 修改 .env 后重启生效
docker compose up -d --build            # 更新代码后重新构建并启动
docker compose down                     # 停止（数据卷保留）
```

健康检查：`curl http://127.0.0.1:8080/api/health` → `{"status":"ok","agent_ready":true}`。

### 3.3 配置 LLM（必做）

**推荐方式**：以管理员登录 → 后台管理 → 模型配置 → 选预设、填 API Key → 「测试连接」→「保存并热重载」。

**备选方式**：编辑 `/opt/Ki-Agent/.env`，把 `LLM_PROVIDER=mock`（离线演示模型）换成真实模型，然后 `docker compose restart app`（若后台已保存过配置，则以后台为准）：

```ini
# OpenAI（gpt-5.6 = 旗舰 Sol；gpt-5.6-terra 更便宜）
LLM_PROVIDER=openai
LLM_MODEL=gpt-5.6
LLM_API_KEY=sk-...

# 或 DeepSeek / Qwen / Moonshot / GLM 等 OpenAI 兼容接口
# （deepseek-chat / deepseek-reasoner 已于 2026-07 下线，moonshot-v1-* 已于 2026-08 下线，请用下列新型号）
LLM_PROVIDER=custom
LLM_MODEL=deepseek-v4-flash          # 或 deepseek-v4-pro / qwen3.7-plus / kimi-k3 / glm-5.3
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=...

# 或 Anthropic（claude-opus-5 / claude-sonnet-5）
LLM_PROVIDER=anthropic
LLM_MODEL=claude-sonnet-5
LLM_API_KEY=...
```

其他常用项：`ALLOW_REGISTRATION=false`（关闭注册）、`JWT_SECRET`（已随机生成，勿泄露）、`APP_PORT`（宿主机端口，服务器上为 8080；改端口需同步在安全组放行）、
`LLM_CONTEXT_TOKENS`（上下文窗口，用于右侧「上下文使用」百分比）。

### 3.4 开源插件 (kcaa) 的直连集成

上游项目发布在 PyPI 的 `kcaa` 包已经打进 `app` 镜像（`backend/requirements.txt`）。应用启动时会在**同一进程内**
导入它、收集全部工具并并入 Agent（日志：`Loaded 116 upstream kcaa tools in-process`）；「资源」弹窗与后台总览中可看到
`开源插件：已加载 · 进程内直接调用`。

- 关闭：后台「系统设置 → 开源插件集成方式」选 `off`，保存即热重载；或 `.env` 设 `KCAA_MODE=off`。
- **KiCad 官方符号 / 封装库已内置在镜像里**（官方 `kicad/kicad:10.0.5` 镜像，装在 `/usr/share/kicad/{symbols,footprints}`，不含 3D 模型包）。
  上游插件和 KiCad 一样通过配置目录里的 `sym-lib-table` / `fp-lib-table` 找库，再从 SQLite 索引提供 `search_symbols` / `get_symbol` / `add_symbol_to_schematic` /
  `list_footprint_libraries` / `search_footprints` / `get_footprint_details`。镜像构建时已把两张表种到 `/root/.config/kicad/10.0/`，并把索引（`kcaa/kicad_symbols.db`、`kicad_footprints.db`）建好，
  启动即可用，不需要先跑 `sync_symbol_index`。
  仍需人在 KiCad 里做的一步：**「从原理图更新 PCB」**（`update_pcb_from_schematic` 是 IPC 工具，要有运行中的 KiCad 图形界面，`kicad-cli` 也没有对应命令）——
  Agent 能从零画好原理图并写好每个元件的 Footprint 字段，下载工程后在 KiCad 里按 F8 生成 PCB 上的封装，再上传回来让 Agent 摆件、布线、DRC。容器里可随时自检 / 重建：
  `docker compose exec app python -m app.kicad.libraries --status`（加 `--sync --force` 强制重建索引）。
  裸机部署：装好 KiCad 后把 `KICAD_APP_PATH` 指到 share 目录（Linux 默认 `/usr/share/kicad`），若从未运行过 KiCad 图形界面，启动时会自动从
  `template/` 拷贝或按目录扫描生成两张表；索引则由 Agent 调 `sync_symbol_index` / `sync_footprint_index` 建，或手动执行上面的命令。
- 需要运行中的 KiCad（IPC 类工具如 `save_document`、`reload_kicad`）在服务器环境不可用，会返回明确错误。
- **`kicad-cli` 已随 KiCad 10 装进镜像**（`/usr/bin/kicad-cli`，构建时会校验版本为 10.x）：`run_drc_check` 自动改用 KiCad 引擎（结果里 `engine: kicad-cli`），
  预览接口 `engine=kicad` 用官方 SVG 渲染，上游的 `generate_pcb_thumbnail`、Gerber / PDF 导出类工具也可用。裸机未安装时退回内置轻量 DRC 与内置渲染，可用 `KICAD_CLI` 指定路径。
  KiCad 10 能读取 10.0 及更早版本的工程；工程文件窗口会显示每个 PCB / 原理图文件的格式版本和服务器兼容状态。若将来上传由更高版本保存的文件，官方 DRC、渲染和导出会在调用 CLI 前给出明确错误并回退到内置能力。
- 构建加速：`.env` 里的 `APT_MIRROR=mirrors.aliyun.com` 会替换 Debian 源（KiCad 包约几百 MB），`KICAD_APT_SUITE` 默认 `trixie-backports`（9.0.8），改为 `trixie` 则装稳定版 9.0.2。
- 如仍想用 MCP 方式（例如插件跑在另一台装了 KiCad 的机器上）：在一个**不含 kcaa** 的环境安装 `requirements-mcp.txt`，
  设置 `KCAA_MODE=mcp` 与 `KCAA_MCP_URL`。

用 Nginx 把 80/443 转发到 8080（服务器上 80/443 目前被另一个容器占用，需先协调）；SSE 与 WebSocket 需要：

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_buffering off;          # SSE 流式必需
    proxy_read_timeout 3600s;
}
```

## 5. 常见问题

| 现象 | 处理 |
| --- | --- |
| 回复固定是「离线演示模型」 | `.env` 仍为 `LLM_PROVIDER=mock`，按 3.3 配置真实模型并重启 |
| 「资源」里开源插件工具数为 0 | `docker compose logs app` 搜索 `kcaa`：常见原因是 `KICAD_VERSION` 未设置或 `KCAA_MODE=off`；后台「系统设置」切回 `direct` 保存即可 |
| 页面能开但发消息报 409 | 同一对话上一条还在处理；等待或点停止 |
| 外网打不开 | 云服务器安全组需放行对应端口（当前 8080 已放行；改端口需同步放行），或改用 Nginx 80/443 |
| DRC 显示 `builtin-lite` | 未检测到 `kicad-cli`（镜像已内置，裸机需自行安装 KiCad），内置 DRC 只覆盖间距 / 占位重叠 / 板边 / 未连接 |
| `search_symbols` 搜不到东西 / `add_symbol_to_schematic` 报找不到符号 | `docker compose exec app python -m app.kicad.libraries --status` 看 `ready` 是否为 true；为 false 时加 `--ensure-tables --sync` 重建（镜像构建时已内置，正常不会出现） |
| 上传的工程识别不到文件 | 目录中需包含 `.kicad_pcb` 或 `.kicad_sch`；ZIP 内不要有 `..` 路径 |
| 忘记密码 / 重置密码 | 见下方脚本，在服务器上执行 |

重置某个用户密码（把 `用户名`、`新密码` 换成实际值）：

```bash
cd /opt/Ki-Agent
cat > /tmp/reset_pw.py <<'EOF'
import asyncio, sys
from sqlalchemy import select
from app.db import User, session_scope
from app.auth import hash_password
async def main():
    async with session_scope() as s:
        u = (await s.execute(select(User).where(User.username == sys.argv[1]))).scalar_one()
        u.password_hash = hash_password(sys.argv[2])
        print("password updated for", u.username)
asyncio.run(main())
EOF
docker compose cp /tmp/reset_pw.py app:/tmp/reset_pw.py
docker compose exec -w /app/backend app python /tmp/reset_pw.py 用户名 新密码
```
